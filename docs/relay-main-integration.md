# Relay messenger source integration

Main includes the modern mobile messenger from origin/v2 (3dfa9ee), viewer-local list time hydration fix (8fbe351), and organization-open public-origin redirect fix (b11503e). The v2 environment-aware app catalog is retained. The older v2 database adapter is superseded by the integrated bounded Neon/Cloud SQL adapter. Reactions use existing message metadata; edit/delete and pin/mute use existing schema fields, so this integration does not require a schema migration.

Production is Cloud Run `relay` at `relay.axxes.club`; staging is `relay-v2` at `relay.v2.axxes.app`. Both should deploy the same reviewed main source with separate image builds. `NEXT_PUBLIC_PUSHER_KEY`, `NEXT_PUBLIC_PUSHER_CLUSTER`, and `NEXT_PUBLIC_AXXES_ENV` are compiled into client code. A production-built image must not be reused for v2 when those values differ. V2 needs its environment-aware catalog (`NEXT_PUBLIC_AXXES_ENV=v2`) and staging public provider credentials. Preserve each runtime's existing Secret Manager mounts, Cloud SQL attachment, identity, auth issuer/cookie domain and DATABASE_URL. Current main pipeline only releases `relay`; a separate v2 build/release must use reviewed v2 build inputs and preserve the v2 runtime configuration.

Feature checks exercise reaction add/remove, invalid inputs, sender ownership, membership denial and tenant-scoped message lookup, plus service-worker exclusion of private pages and APIs from cache. Existing auth/context/access checks and typecheck execute inside the Linux build stage. The service worker stores static assets only; push/realtime requires the existing Pusher server and public client environment values to agree.
